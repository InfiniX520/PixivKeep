## 1. S0：主智能体串行冻结的共同契约

输出一份新日期契约，不在旧审计报告上改历史。每个定义必须写生产者、消费者、缺字段、矛盾字段和过期证据的行为。

| 契约 | 必须回答 | 禁止的含混答案 |
| --- | --- | --- |
| 写入能力 | 哪个对象/父目录被授权；保护从什么时候持续到什么时候；SQLite 怎样使用这个能力 | “写完会再查身份” |
| 观察预算 | 按文件还是命令；读前额度、实际读量、取消/时间终态；decoder 如何回传开销 | “最后加 file size 就行” |
| 页完成 | page identity、expected 内容代次、observed 代次、策略与根版本如何匹配；冲突如何解 | “有 SHA 就算已验证” |
| 覆盖数据来源 | V2 job/batch/snapshot 的确切主键、事务快照与分页口径；legacy 支持的范围 | “都有 run_id，接上即可” |

## 3. W1：先保护实际写入，再处理清理

实施步骤：

1. 沿公共 `backup_library(mode=auto/online_backup)` 追踪目标目录创建、claim、SQLite connect、backup、PRAGMA、验证、发布、失败清理。列出每次按路径重新打开的位置。
2. 选择能在实际 Windows 文件系统证明的写能力方案。若采用持有句柄，应验证共享模式是否确实阻止删除/重命名替换，又允许 SQLite 自己写入；不支持时拒绝或采用经测量的替代方案。不要只写一个 `is_owned()` 检查掩盖检查到使用间的窗口。
3. 验证 parent 仍是 adopt 的目录，并维持到子文件创建/后续写入。拒绝不能证明的目录/重解析点，不通过自动重建根路径来继续。
4. 对 SQLite 自动产生的 journal/WAL/SHM 单独声明所有权策略。不能回到“看见同名旁车就认领并删除”。异常保留哪些字节、记录什么事实、后续如何回收，应可核对。
5. 正常在线备份和 file-group 路径都跑；保留源库并发写入与备份一致性原测试；用实际 verify 验备份可读，不只 assert 一个返回路径。

验收必须包含：claim 后替换目标、connect 前替换父目录、写完后替换、foreign sidecar、SQLite connect/backup/close 异常、源库 WAL 活跃、取消、清理拒绝。每个反例确认外部哨兵 SHA 与大小不变。

**允许替换操作被系统保护拒绝。** 原始 EA-01 钩子在当前漏洞树会成功；修复后若保护使它不能成功，新增一个证明该拒绝的测试，同时保留“没有 foreign write”的最终断言和原始红基线。不能为了让 hits=True 而削弱锁。

## 4. W2：把计费放到真正的读取点

先画一次严格验证的调用序列：observe→before hash→structure→decode→after hash→最终判定。给每段唯一的预算消费规则；禁止无意重复 charge，也禁止因换了回执类型把读量丢成 0。

- 用受限 reader 或等价的读循环，`read_size <= remaining`；取消/时间每块检查。阶段进入检查仅是第一道，不能代替循环检查。
- Decoder 返回事实和真实消耗，统计截断/失败前已读取的字节；读取抛异常也不把已消费计数归零。
- 预算不足以完成后一哈希时，返回 `unknown/bytes_limit`，最终退出非成功。不要在最终 hash 超额后仍使用稳定性成功覆盖预算终态。
- 取消后允许一个已发出的有界 read 完成，但禁止接着读完整文件。明确最大块与可测响应上界，不用纳秒级脆弱时限作为门槛。
- 若多文件 CLI 共享一个预算，保持跨文件单调；若契约明确 per-file，输出和参数帮助必须同样标明，不叫整命令总预算。

验收矩阵：0/恰好/少 1 字节预算；前哈希/结构/解码/后哈希分别耗尽；每阶段取消与时钟到期；合法 PNG、损坏 PNG、未知格式；成功/失败计数都与 instrumented read 求和一致。禁止通过 mock `_sha256` 整个函数来证明真实 read 可取消。

## 5. W3 + I：先决定当前批次的事实，再接 UI

1. 从真实 `LibraryRepository` 的 job/batch/follow snapshot/source progress/page delivery/artifact 关系导出事实，不从 legacy `crawl_runs` 推测 V2 的进度。
2. 有些事实 V2 暂未保存时明确 unknown 并写缺口；不得拿作品数代页面数，或从文件名计数补出“全集”。对同一报告使用一致只读视图，避免 job 读完之后另一个事务推进 pages 形成混代报告。
3. 页事实携带 expected 和 observed 内容代次；匹配规则与已有核验/复用规则一致。正向同版本案例与异版本/冲突/缺版本案例必须同时存在。
4. 让 Runtime 返回 provider、job_id、batch_id、snapshot 等报告来源。UI 选中任务即可查看，缺失来源提示可理解原因，不要求用户到旧库抄 run_id。
5. 现有显式旧库 CLI 如保留，命名 legacy 模式并测试；它和 V2 adapter 共用纯报告引擎，但不共享错误的默认数据库路径。
6. 主智能体接 UI/CLI，保持用户认可的视觉布局和无图片预览约束；只改数据来源和必要选择交互，不借此再造前端。

验收至少：空新装、仅 V2 合成数据、只有 legacy、两者同时存在而结论不同；多个 job/批次；活动任务读时推进；完整一页、缺页、旧 SHA、相同状态不同 SHA；按 UI 按钮走真实 Runtime。接线测试可以使用合成 DB，但不能把 runtime.coverage_summary 整个 mock 掉。

## 6. W4：集合守恒、不可变和验证续跑一起做

先冻结字段再修算法，避免批次和范围各自猜字典形状。

集合不变量：`pool - done = planned_union ∪ explicitly_remaining`，两边无遗漏；所有批次互不重复；step keys 与该批 members 一致。按实际选入数量推进游标，或先求真实容量再切块。容量为零时停止并记录剩余，不能生成无穷空批。

状态不变量：applied 意味待核验，verified 才代表读回确认；错误、冲突和人工修改不得被静默当 completed。resume 选“还有安全动作可做”的对象，rebuild 要允许持久化的合法前进。unknown write outcome 应先 reconcile，不能直接重发写操作。状态最终值和 batch.status 统一计算，别只在 paused 分支更新。

对象不变量：所有输入深拷贝/规范化，嵌套列表用不可变表示；as_dict 递归输出全新可 JSON 化结构。GroupScope 属性不可赋值，fingerprint 与规范化的身份字段同源。反序列化校验 steps、blocks、group_pairs、source、完整性枚举，非法形状用稳定类型化错误。

Scope 不变量：完整性建立在所选分区事实一致上。核对 memberships 每组集合与 artist 行、visibility/catalog，坏行不能当空组。`ensure_current` 区分成员变化、证据不足、同成员但完整性降级；这些不能都折叠成 fingerprint 相同。

验收：pool 0/1/5/21、预算0/1/小于max_artists/足够、done重复/乱序；每个合法状态中断后序列化重启；applied→verify；导出对象/构造入参/嵌套policy修改均不影响原对象；成员相同不同visibility；complete标志与成员冲突；正常完整快照往返。

## 7. W5：规则输出不能越过审阅证据；报告组合必须对齐

保留既有 review 的实际查看声明、样本 SHA、min(12, available_works) 独立作品约束。新分类函数若只接受 tags 就只能输出建议分数，不应输出可进入计划的 `needs_more=False`。推荐由验证后的审阅对象提供视觉证据充分度，再与规则匹配分开输出。

必须测试零作品、重复同作品多页、11/12个独立作品、已证实仅有3作品的画师、unknown available_works、样本 SHA 不匹配、旧 snapshot/rules_version。低作品量不是一概拒绝，也不能由调用方随手填写 available_works 就降低门槛。

报告入口先验证三份输入：Batch、GroupScope、decisions。不允许依靠打印 `covers_batch=False` 来替代拒绝；更大范围覆盖子批次可以合法，但账号/快照/规则来源必须符合冻结契约。`kind/action/needs_human` 应按决策真值表验证，不相信独立字段各自枚举合法即组合合法。

退出码明确分开：输入不合法、输入合法但证据不足、报告可用、I/O 失败。报告可用不意味着写回完成；输出显式保留 website_write_back 未证明。缺字段/null/错类型/非法UTF-8/损坏JSON要类型化处理，不捕获后伪造空成功。

## 8. 集成、复核与交付门槛

按 W1→W2→W3→W4→W5→I 的依赖顺序合流；真正无共享文件的包可并发开发。每路提交前附准确基线、修改范围、实际命令与结果，不能只报“全绿”。有接口变更必须同步 S0 和相邻消费者。

主智能体验收顺序：语法/类型（仓库已有配置范围）→定向反例→相关旧回归→现有整套→Tk 按已验证进程组织→独立整链。然后按工作区要求用只读上下文 fork 对照冻结契约逐行审 diff；出现问题退回原开发上下文修复。不能在预算不足时把未完成复核写成通过。
